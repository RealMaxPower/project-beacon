Handoff — components, variants, provenance

What to build, and which parts of it are actually true.

Every value in these mocks is tagged by where it came from. Ship the REPO ones as they are. Replace every ILLUSTRATIVE one before this goes in front of anybody.

01

Provenance, and what it obliges you to do

REPO
Verbatim from README or CHANGELOG. Commands, counts, verdict outputs, assertion ids that appear in the docs, the compatibility table, the limitations text.
Ship as-is. Pin it to a test.
PROPOSAL
From the pre-build proposal — designed, not necessarily shipped. The normalised event vocabulary, the scenario YAML shape, the five-level compatibility model.
Check against code before it reaches a user.
ILLUSTRATIVE
Mine. Message bodies, timings, run ids, most assertion ids, the JSON shapes in expert mode, all UI copy.
Replace before launch. Non-negotiable.
The one that matters most: expert mode is entirely illustrative. It is the view built to be trusted by people who will not trust a friendly summary — a plausible-looking evidence.json that does not match the real one is worse than no expert mode at all.

Tailwind reads the tokens, it does not redefine them
theme.extend.colors = { bg, surface, sunken, line, "line-strong", text, "text-muted", "text-faint", accent, pass, fail, inc, ... } // each mapped to var(--name)
So bg-surface and text-fail follow the theme automatically, and dark mode stays one attribute on the root element.

07

Open, and blocking

BLOCKINGThree real files, and expert mode becomes true
One evidence.json, one events.json, one scenario.json from an actual run. Everything else in the prototype survives without them; expert mode does not.
DECIDED40 adversarial subjects, not 21
The brief said 21; the README says forty and 40/40 verdicts correct; the CHANGELOG lists the 21 as fixed documentation drift. Confirmed 40. Pin it to a test so it cannot drift again.
RECOMMENDEDMark A — Sweep
Concentric arcs from a fixed origin. It survives the rename that trademark screening may force, holds at 16px, and doubles as the run-in-progress spinner. All four candidates are drawn in the design system.
NOT BUILTKnown gaps in this prototype
The marketing site is desktop-width and does not reflow — mobile is mocked separately as device frames. Marketing scenario cards do not launch that scenario in the playground. The playground is dark-only. None of these block a build; all three are half a day each.
